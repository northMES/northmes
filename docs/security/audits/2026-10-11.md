# Internal security audit, 2026-10-11

The first internal audit under [ADR 0076](../../adr/0076-secure-development-lifecycle-with-a-security-note-per-change-a-controls-index-and-an-internal-audit-each-release.md). It read the code at `main` 8bed540 and 507a62e: the backend, the web, the scripts, CI, `infra/` and the ADRs. The yardstick was the maintainer's secure-development guidelines (IEC 62443-4-1, ISO 27001 and SOC 2 development controls, OpenSSF Best Practices).

- **Method:** a read-only review in three parts (the decisions and documents, the backend code, and the web, CI and infrastructure), including the installed sources of Better Auth 1.7.6, GraphQL Yoga 5.24.1 and ws 8.21. Nothing was run against an installation.
- **Context:** NorthMES is not released or installed anywhere, so no finding affects a running installation.
- **Tracking:** the findings are tracked under [#473](https://github.com/northMES/northmes/issues/473), and the [controls index](../README.md#controls-index) holds the state of every control.

## Summary

No finding is critical or high.

The design is thorough. What is built is sound: deny-by-default authentication, short-lived pinned JWTs, row-level security with least-privilege database roles, Zod contracts on every input, masked errors, secret files, a strict CSP and hardened CI.

The main gaps are controls that the ADRs decide but the repository does not build yet:
- the audit trail and security events;
- structured logs;
- `SECURITY.md`;
- the supply-chain checks;
- a threat model.

The audit also found four medium code findings, B1 to B4.

## Controls found in place

- **Authentication:** a global principal guard denies by default, and only the shell and the new-password route are public. JWTs are EdDSA, looked up by key id, with the issuer and audience pinned and a 5-minute lifetime. The principal is re-read on every request, so a block or a role removal applies at once. The plant header is checked against the user's grants.
- **Authorization:** the command bus checks the permission at the target row's scope before and after the row lock, and checks the version. Validators fail closed. No one can grant a permission they lack, and the last Company admin is protected.
- **Database:** scopes are set per transaction with `set_config(..., true)` from bound values. `nm_app` owns nothing and cannot bypass row-level security, and `nm_owner` is never used at run time. SECURITY DEFINER functions pin `search_path` and revoke access from public.
- **Input and SQL:** Zod contracts parse every command. The list kit caps page size, sort entries and search length, and escapes LIKE patterns. No SQL is built from user input.
- **Errors and secrets:** errors are masked; secrets come from files that others cannot read; dev secrets are refused in production; `DATABASE_URL` may not carry credentials; passwords never reach the log.
- **Web:** the CSP has no `unsafe-inline` or `unsafe-eval`. The page loads no third-party scripts or fonts and has no HTML injection sinks. Requests omit cookies, and the UI shows only error codes and correlation ids.
- **CI:** read-only tokens, actions pinned by SHA, no `pull_request_target`, pull request text passed through `env`, and fork pull requests on GitHub-hosted runners, all enforced by `test/meta/workflows.test.ts`.
- **Supply chain:** a frozen lockfile from the registry only, a strict catalog, a 14-day release age, and install scripts denied.
